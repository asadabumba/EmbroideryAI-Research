# Security policy

## Supported scope

This public snapshot is research software and is not a production embroidery writer. Security reports should focus on vulnerabilities in the public code, tests, packaging, or automation.

## Reporting

Use GitHub's private vulnerability reporting feature when it is available for the repository. If private reporting is unavailable, open a minimal issue asking the maintainer for a private reporting channel; do not publish exploit details, credentials, customer data, or proprietary artifacts in the issue.

## Sensitive material

Do not attach passwords, API keys, access tokens, private keys, memory dumps, proprietary executables, or customer embroidery files to a report.
